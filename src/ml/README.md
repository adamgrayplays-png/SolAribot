# SolAribot ML Decision Layer

## Model Card

### Overview

The ML Decision Layer provides AI-powered scoring for Solana arbitrage
opportunities. It combines three specialised models to predict execution
success, estimate slippage, and detect fake/unexecutable opportunities.

### Models

| Model | Algorithm | Output | Latency |
|-------|-----------|--------|---------|
| Execution Success Predictor | XGBoost Binary Classifier | P(success) [0-1] | <2ms |
| Slippage Estimator | XGBoost Regressor | Slippage fraction [0-0.10] | <2ms |
| Fake Arbitrage Detector | Random Forest Binary Classifier | P(fake) [0-1] | <2ms |
| Opportunity Scorer | Combinatorial formula | Score [0-100] | <0.1ms |

**Total inference:** <5ms per opportunity (single-threaded).

### Features

#### Success Predictor (7 features)
- `congestion_level`: Recent avg priority fee (log-scaled)
- `pool_liquidity_token_a`: Token A pool depth (log-scaled USD)
- `pool_liquidity_token_b`: Token B pool depth (log-scaled USD)
- `trade_size_relative`: Trade size relative to pool TVL [0-1]
- `route_hist_success_rate`: Historical success rate for this route [0-1]
- `hour_sin`, `hour_cos`: Cyclical time-of-day encoding

#### Slippage Estimator (12 features: 5 numeric + 7 DEX one-hot)
- `pool_depth_usd`: Total pool liquidity (log-scaled)
- `trade_size_usd`: Trade size (log-scaled)
- `order_book_imbalance`: Buy/sell volume ratio
- `volatility_1min`: 1-min price volatility
- `trade_size_relative`: Trade/depth ratio
- `dex_type_encoded`: One-hot (jupiter, raydium, orca, meteora, lifinity, openbook, phoenix)

#### Fake Detector (6 features)
- `price_deviation_from_oracle`: % diff from oracle price
- `order_book_spread`: Bid-ask spread (bps)
- `min_liquidity_path_depth`: Thinnest leg in route (log-scaled USD)
- `recent_pool_manip_events`: Count of large swaps in last 10s
- `profit_to_liquidity_ratio`: Expected profit / min liquidity
- `route_depth_imbalance`: Max/min depth ratio across route

### Scoring Formula

```
score = expected_profit × P(success) × (1 - slippage_penalty) × (1 - fake_probability)
```

Where:
- `slippage_penalty = min((slippage_estimate × 10)^1.5, 1.0)`
- Score normalised to [0, 100] via adaptive min-max scaling
- Dynamic threshold adjusts based on congestion (+ up to 20 pts) and volatility

### Training Data

Models are trained on **50K synthetic samples** (configurable) generated with
realistic Solana DeFi parameters:
- Pool TVL: $10K–$50M (log-normal)
- Trade sizes: 0.1%–10% of pool
- Congestion: 1K–500K microLamports
- Volatility: 0.05%–2%
- Fake opportunity rate: ~35%

### Performance (expected on synthetic data)

| Model | Metric | Expected Value |
|-------|--------|----------------|
| Success Predictor | Val AUC-ROC | >0.80 |
| Slippage Estimator | Val MAE | <0.005 (<0.5%) |
| Fake Detector | Val F1 | >0.85 |

### API

The models are served via FastAPI on port 5000:

```
POST /score          — Score single opportunity → {score, success_prob, slippage, fake_prob, actionable}
POST /score/batch    — Batch scoring
GET  /health         — Health check
GET  /models/info    — Model metadata & feature importance
```

### Integration with Orchestrator

The TS orchestrator calls the ML server at `http://localhost:5000/score`
before executing any arbitrage trade:

1. Detect opportunity → extract opportunity data
2. POST to ML server → get score + predictions
3. If `actionable == True` → execute trade via Rust engine
4. Monitor execution → feed outcome back for model retraining

### Usage

```bash
# Activate venv
source .venv/bin/activate

# Train models
cd src/ml
python train.py

# Start server (background)
nohup python serve.py > /tmp/ml_server.log 2>&1 &

# Test
curl -X POST http://localhost:5000/score \
  -H "Content-Type: application/json" \
  -d '{"expected_profit_usd": 50.0, "congestion_level": 10000, ...}'
```
